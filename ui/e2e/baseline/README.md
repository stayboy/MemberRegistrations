# Live-build screenshot baseline

Generated by `ui/e2e/capture.spec.ts` against the production build, at the viewport of the local mock
each screen is compared with. **Never edit these files by hand**; regenerate them.

```powershell
npm run ui:capture
```

The capture runs on `vite preview` under `/MemberRegistrations/`, with the seeded session and the
stubbed gateway from `ui/e2e/fixtures.ts`, `deviceScaleFactor: 1`, the locale pinned to `en-US`, the
timezone to `UTC`, reduced motion, animations disabled and the caret hidden. It is a separate
Playwright config (`ui/playwright.capture.config.ts`) so `npm run ui:e2e` never writes images.

`member-add` and `series-detail` use the mocks' real PNG dimensions (1200 px and 1000 px tall) rather
than a rounded 900 px, because those screens scroll below the fold. `imports-batches` has no local
mock; its viewport follows the other 900 px screens.

`v2-shell/17-find-contact.png` has no capture: the UI has no `Find by contact` control yet, although
FR-79/AC-48 specify one. The members toolbar currently offers name/member-number search only.

Two consecutive runs can differ by roughly 6–30 antialiased border/corner pixels on some cards (usually
under 16); the content and state are stable. There is no pixel gate yet, so this folder is a review
artifact, and any future gate must calibrate against that drift.

The mock folder is git-ignored and local: the durable comparison record lives in the ticket-19 round
doc, not here.
