# Release claim - `v0.1.0-mvp` (local stack)

**Status: DRAFT - the tag waits for the owner's sitting.** The claim below is what `v0.1.0-mvp` would
certify. It is not a tag yet: cutting it is a verb of its own (`AGENTS.md` section 9), and one gate stands
in front of it - the owner's verdicts over the **32 auto-signed** mock states
(`documents/parity/auto-signed-review.md`), which by rule must end `signed` or drop to `target` before a
tag may describe that catalogue as settled.

## What this release certifies

The **local Docker Compose stack**, reproducible from a clean volume, with its screens compared against
their drawings - and not a deployed environment. Production, the GitHub Pages deploy, the three production
secrets and the production release, including its tag, are out of scope until 0.3
(`documents/specs/member-registrations-ui.md` OS-21; owner, 2026-11-16). The tag this file drafts certifies
nothing about production, and is cut on its own instruction.

Someone quoting this tag should be able to read the next four sections and know exactly how far it goes.
That is the point of writing it this way: a claim that names its scope can be checked, and one that does
not is read as everything.

## 1. What was verified, and how

| Claim                                         | Command or artefact                    | Result                                                                                                                             |
| --------------------------------------------- | -------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| The stack builds and boots from nothing       | `compose down -v` then `up --build -d` | db healthy, `migrate` exits 0, `/health` answers `200`                                                                             |
| The API works against the real schema         | `npm run smoke:local`                  | 16 of 16 checks                                                                                                                    |
| The gate is green on `main`                   | `npm run verify`                       | 7 of 7 steps: skill, check-round, format, lint, typecheck, test, build                                                             |
| The tests pass                                | `npm run verify`                       | 824 passed, 7 skipped, in 60 files                                                                                                 |
| The UI routing and accessibility suite passes | `npm run ui:e2e`                       | 66 tests in 10 files - axe, routing, the responsive checks and the page flows; the capture lane is a separate `npm run ui:capture` |
| Data survives a restore                       | `npm run drill:backup`                 | 90.2 KiB dump restored into a scratch database, 4 probed tables exact, 3.1s                                                        |

**The drill is a rehearsal, not a habit.** It ran once, against a thin local stack (1 member; 3 of the 4
probed tables empty). It proves the script works; it does not prove a backup taken under load will restore.
Repeat it before trusting it with data anyone would miss.

## 2. What was compared, and what was not

`documents/parity/comparison-pack.md` lists **21 surfaces**. **Fifteen of them were read** image against
image; the other six could not be, for the reasons below. A row is claimable only where a **live source**
and a **signed mock** both exist.

**Claimed - read, and matching or fixed in this release (14):** the members list; the events list; the
activity detail for an event; the headcount dialog; the attendance import panel; settings; the five shell
states (light, dark, collapsed, mobile, meadow accent); the shepherding officers page, roster and church
report.

**Read, with one exclusion parked (1):** the activity detail for a **series**. Its schedule cell now agrees;
its occurrence rows still show dates only, because `OccurrenceListDto` carries no session ids, so the
`Record headcount` and `Import` controls the drawing puts on each row have nowhere to attach. That is the
per-occurrence headcount item in `documents/backlog.md`, and it is a wire change, not a drawing fix.

**Not claimed - no signed mock exists (5):** member detail, add and edit member, the contacts dialog, the
mark-attendance dialog, and the import batch list. They were built from the spec and are exercised by tests;
nobody has compared them to a drawing, so this release does not say they are right.

**Not claimed - the legacy prototype captures** that predate the build and have no live source. They can be
neither re-cut nor compared; noting their consistency with the design language is not parity.

**Not claimed - the USSD simulator.** It is a development-only screen with no mock of its own, and this
claim excludes it.

The five surfaces with no signed mock, the legacy captures and the simulator are carried, with what is
unproven, why it is accepted and what would close it, in `documents/parity/unclaimables.md`;
`tests/meta/parity-claim.test.ts` fails if one of those rows disappears. The series occurrence exclusion is
a different kind of debt - a wire gap rather than a missing drawing - so it lives in
`documents/backlog.md` with its trigger.

## 4. What was deliberately cut

**One difference is cut, not fixed** (owner, 2026-11-16): a page's single verb renders as a secondary button
in the build and as a filled primary in the drawings that show it - the five shell states and the members
list, **six catalogue entries** in all. Each of those entries now records that the drawing is behind the
build, so the contract moves with the build rather than being waived in silence. The next release that
touches `PageFrame` owes one line, not a round.

## 5. What the gates do not measure

- **Accessibility is claimed for the routes audited and no others.** `ui/e2e/axe.spec.ts` audits the members
  list, the events list, the offerings list, one event detail, the shell in four accents by two schemes, the
  Offerings count page and its record dialog, and the sign-in gate in three states (idle, link sent, expired
  session) - each in **both schemes**. It does **not** audit member detail, member add/edit, archived members,
  the series form, the imports pages, the three shepherding pages, the USSD pages other than offerings, admin
  ministries, settings, the not-found route, the gate's signing-you-in and signed-in states, or the gate's
  transport-error bar. The full scope sentence is in `documents/rounds/mvp-local.md`.
- **One end-to-end assertion is parked as flaky**: the import panel's deep-link opening
  (`AttendanceImportRedirect`, `import=<date>`). It passes alone and fails under a parallel run; two
  attempts did not establish why, and the round parked rather than spend a third. It is a known gate risk,
  not a clean pass - `documents/backlog.md` carries it with its trigger.
- **Parity is visual.** It says a screen looks like its drawing. It does not say the behaviour behind the
  screen is right; that is what the 824 tests and the smoke suite are for, and they cover different ground.
- **The mock catalogue is not fully owner-signed.** 54 states: 15 owner-signed, 32 auto-signed, 7 reference.
  Auto-signed is a temporary value; the sitting that retires it is the gate named at the top of this file.

## 6. The tag

`v0.1.0-mvp` would name commit `main` at the cut, after the sitting. It certifies sections 1, 2 and 3 above,
carries sections 4, 5 and `documents/parity/unclaimables.md` as named exclusions, and says nothing about
production.

When the tag is cut, this file's status line changes and nothing else in it needs to be true again - that is
